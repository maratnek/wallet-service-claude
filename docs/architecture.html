Wallet Service Topology

Async-only gRPC + Kafka pipeline. wallet-service only validates and publishes; wallet-worker is the sole owner of state; the client talks to Kafka directly for results. One W3C traceparent rides the whole loop.

3 go services kafka otel + jaeger trace_id = msg_uuid

trace_id := msg_uuid

Since internal/telemetry/idgen.go, the client seeds the root span's trace ID with the same UUID it already uses as msg_uuid to match a command to its result. Every hop above inherits it — so GET /api/traces/<uuid without dashes> opens the full trace directly, no tag search needed. Falls back to a random trace ID whenever nothing seeds the context.
